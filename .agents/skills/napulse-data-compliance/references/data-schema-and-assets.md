# Схема данных, документов и медиа-ассетов

## 1. Источники данных в `js/main.js`

- `TEAM.organizers`: `{ name, role, photo }` — сейчас 5 записей (`organizers/org-1` … `org-5`).
- `TEAM.volunteers`: `{ name, photo }` — сейчас 6 записей (`volunteers/vol-1` … `vol-6`).
- `JURY`: `{ name, dir: 'vocal' | 'dance', photo, regalia: string[] }` — сейчас 6 записей (`jury/jury-1` … `jury-6`).
- `GALLERY`: `{ src, year, caption }` — сейчас 12 записей (`gallery/g-YYYY-1..4`).
- `ARCHIVE`: `{ year, roman, pending?: boolean, files?: [{ type: 'pdf' | 'xlsx', dir: 'vocal' | 'hore', name, size, href }] }`.
- `AGES`, `DANCE_STYLES`, `VOCAL_NOMS`, `FORMS`: поля форм заявки. Должны быть строго синхронизированы с действующей редакцией `docs/polo.pdf`.

## 2. Правила работы с документами (`docs/`)

1. **Положение (`docs/polo.pdf`):**
   - Сохранять текстовый слой читаемым (UTF-8, без искажённой кодировки шрифтов при экспорте из графических редакторов).
   - Указывать актуальные даты, порядковый номер фестиваля (римской цифрой), состав жюри, номинации, возрастные шкалы и реквизиты организатора.
   - Оптимизировать размер файла (ориентир до 1–2 МБ).
2. **Расписания (`docs/raspisanie-*.docx`):**
   - Имена файлов и подписи ссылок в `index.html` (`.hero-schedule__links`) и атрибуты `download="..."` должны совпадать по датам и направлениям.
3. **Ведомости результатов (`docs/results-ГОД-vokal.*`, `docs/results-ГОД-horeografiya.*`):**
   - **Запрещены побайтовые дубликаты** между `vokal` и `horeografiya`: в вокальных ведомостях — только вокал, в хореографических — только хореография.
   - При обновлении файлов обязательно пересчитывать поле `size` в массиве `ARCHIVE` в `js/main.js` (формат `XX,X КБ`, делитель `1024`).
   - Не оставлять демонстрационные/чужие шаблоны (например, из других городов) под видом реального архива.

## 3. Правила работы с изображениями (`images/`)

- Слоты фото используют базовый файл `.svg` и растровый файл (`.jpg`, `.jpeg`, `.png` или `.webp`) с тем же базовым именем.
- **Один растровый файл на слот:** нельзя держать одновременно `name.jpg` и `name.png`, так как `upgradePhoto()` запускает параллельную загрузку расширений без отмены.
- Рекомендуемые размеры: портреты — от `600×600` (1:1), галерея — `1200×900` (4:3), площадка — `1200×800` (3:2).
- Неиспользуемые ассеты (`poster.png`, `logo-mark.png`) либо подключаются в разметку, либо документируются/удаляются, чтобы не раздувать репозиторий.

## 4. Синхронность данных между файлами

При изменении даты или номера фестиваля обязательно проверять все точки:
- `index.html`: `<meta name="description">`, `.hero__kicker`, `.hero__meta`, `.hero-schedule__links`, `.footer__brand`, `.footer__bar`;
- `js/main.js`: `initCountdown()` (`new Date(year, monthIndex, day, hour, min, sec)` — помнить, что месяц в JS считается с `0`), `applicationText()`, `ARCHIVE`;
- `docs/polo.pdf` и `docs/raspisanie-*.docx`.
